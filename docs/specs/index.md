- [F-PLATFORM-004 Catalog provisioning via catalog-requests — a request-file-triggered pipeline that creates a new Unity Catalog catalog](F-PLATFORM-004-catalog-provisioning-requests.md) — draft — since built: a `catalog-requests/` folder, a nine-field YAML request per catalog, and a push-triggered pipeline reusing apply.yml's changed-path shape to run three new capabilities (`create_catalog`, `create_schema`, catalog-level tagging) — the first operations the platform performs on something other than an already-existing table; scoped to a fake-client-only demo with no live path at all; open questions resolved through rev 3 — the metastore-level grant + live provisioning handed off whole to F-PLATFORM-005 (now drafted), per ADR-009's least-privilege/layer-separation precedent. Rev 4 is the first change driven by watching the built system rather than reasoning about a proposal: `business_area` and `environment` were required, reviewed, and then written nowhere in Unity Catalog at all, so they now join `sensitivity` as catalog tags in the same merge write — properties rejected because that bucket is for pointers needing re-resolution, not searchable classification values; `region` deliberately left out so nothing implies region-aware provisioning. The tag write is now unconditional, so every valid request plans exactly three statements, and the create-only rule's single exception covers three converging fields instead of one. Owner hector.
